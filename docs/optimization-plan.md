# OPT 推理优化施工点

当前范围：O0–O2。定位止于公开 SDK 调用、参数、耗时与返回结果。
O3 及以后待单独启动；不推测或修改 SDK 内部实现。

| 编号 | 工作 | 验收与依赖 |
|---|---|---|
| O0 | 冷启动后先 selection、再 32-token 全模型基线；记录 boot、SDK/binary hash、等待、CPU token、TTFT 与 tokens/s | 权限恢复后运行；数值正确与延迟异常分开报告 |
| O1 | 阶段/轮次心跳、独立 selection 入口、SDK 调用计时；分开初始化、prefill、首预测、decode、释放及各层组件 | 不新增张量读回；计时开关对照；API 次数匹配实际 consumed/predicted token；纯主机单测 |
| O2 | 冷启动后长等待仍复现时，缩减 selection 调用序列；与三类既有内存诊断统一说明，各自独立执行 | 未复现则保留证据与诊断入口，不宣告根因修复、不新增猜测性的测试矩阵 |
| O3 | 小图验证产生 K/V、原位追加和 Attention 读取的图内依赖 | 无完整 KV 复制/双缓冲；检查是否避免逐 token 重新验证图，验证历史保持与 reset |
| O4 | 完整 decode 合为一个 SDK 图；算子构造和图执行解耦，保留必要输出、按需开放诊断输出 | 依赖 O3；每 decode 步一次图执行；CPU/KV、初始化、内存与吞吐对照 |
| O5 | 固定小块 prefill，验证因果 mask、连续 KV 写入及尾块，再测 32-token 输入 | 每块一次整图；检查 prefill/decode 权重和 KV 共享；验收首 token、后续 decode 和 TTFT |
| O6 | 固定相同输入输出，对照 capacity 64/128；收益明确再考虑分桶/有效前缀 | 不用全量复制、逐步重编译或不断增多的图数量换取收益 |

执行：O0 → O1；O2 按观测触发。之后 O3 → O4 → O5；O6 依计时证据决定。
单图目标指一次完整 decode 或一个 prefill 块；自回归循环仍由主机调度。

O0–O2 的运行命令、日志字段及证据保存在
[SDK 计时与等待诊断](../tests/np101-sdk-timing.md)。三类内存复现沿用
[内存诊断](../tests/np101-memory.md)，不重复实现扫描器或分配框架。
